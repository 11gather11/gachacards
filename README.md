# GachaCards

画像を 1 枚入れると、レアリティ演出つきのカードが動く**透過 WebM** を書き出すブラウザアプリ。
Streamlabs のアラート画像として使うことを想定している。

レアリティはパチンコの保留玉カラー（白 → 青 → 緑 → 赤 → 金 → 虹）で、
信頼度が上がるほど枠色・グロー・光沢・震え・フラッシュ・パーティクルが派手になる。

## 使い方

```bash
pnpm install   # 初回のみ
pnpm dev       # http://localhost:5173 が開く
```

1. 左パネルに画像をドロップする（枠を隙間なく埋めるまで拡大され、はみ出したぶんは切られる）
2. レアリティを選ぶ
3. 向き・尺・サイズ・fps・画質を決める
4. 「透過 WebM を書き出す」を押す
5. 結果が市松模様の上で再生されるので、気に入ったら「保存」を押す

向きは横長と縦長を選べる。配信のアラート枠は横長なことが多いので、既定は横長にしてある。
カードの縦横比は 2:3 のままで、向きだけが入れ替わる（横長なら 3:2 に寝る）。

書き出しボタンだけでは保存されない。何本か試して良かったものだけ保存する流れにしてある。

### 切り取り位置

画像は枠を隙間なく埋めるまで拡大されるので、縦横比が枠と違えば必ずどちらかが
はみ出す。縦長の写真を横長のカードに入れると上下が切れ、上のほうにある顔が
入らないことがある。

画像を入れると、アートワークの下に**切り取り位置**のつまみが出る。左へ寄せると
画像の上（横長画像なら左）が残る。**はみ出していない軸のつまみは出さない。**
動かしても何も起きないつまみが並んでいると、効かない設定だと思われるため。

既定は 0.5（中央）で、これまでと同じ見え方になる。

### 同じカードを別の日に作り直す

パーティクルの配置は「パーティクルの種」（seed）だけで決まる。同じ seed を入れれば、
何日後でも、別のブラウザでも、まったく同じ配置になる。

- seed は数値として表示されるので、そのまま控えるか、手で入力し直せる
- 🎲 ボタンは新しい seed を引く（値は表示されるので、引き直しても元に戻せる）
- 設定（レアリティ・入りの演出・向き・尺・サイズ・fps・画質・カード名・切り取り位置・seed）はブラウザに自動保存され、
  次に開いたときに復元される。アートワークだけは容量の都合で保存されないので入れ直す
- 書き出したファイル名に seed が入る（例: `dragon-gold-s70883.webm`）ので、
  出来上がったファイルからでも seed を辿れる

### モーションブラー

`fps` の隣の「ブラー」で なし / 弱 2x / 中 4x / 強 8x を選べる。既定は弱。
プレビューにも同じブラーが掛かり、露光幅は書き出しの fps に合わせてあるので
画面と出力がズレない。

サンプル数がそのまま描画回数の倍率になる。900×700 / 30fps / 8 秒の書き出しで、
なし 1.5 秒に対し 4x で 2.6 秒ほど。

以前は強く掛けると暗部に縞が出ていたが、中間レイヤーを float16 で持つようにして解消した
（後述）。8x では虹だけプレビューが 60fps に届かなくなるが、再生位置は経過時間で
進めているので速さは変わらず、書き出しは実時間と無関係なので出力にも影響しない。

### Streamlabs での設定

1. Streamlabs のダッシュボード → **Alert Box** → 対象のアラート（Follow / Sub / Donation など）を開く
2. **Image** に、書き出した `.webm` をアップロードする
3. **Alert Duration** を、書き出した尺と同じかそれ以上にする（短いと演出の途中で消える）

サイズの既定を **800×600**（「標準（アラート向け）」）にしてあるのは、Streamlabs の
アラートボックスの慣習サイズがこれだから。ここに合わせておくと **Image Size 100%**
で収まる。それより大きいプリセットを選ぶと 100% でははみ出すので、Image Size を
下げるか、ブラウザソース側を広げることになる。

### 文字を上に寄せる

アラートの文字は動画の下に置かれるが、この素材は下側に透明な余白（グローのぶん）が
あるので、そのままだと文字が離れて見える。Streamlabs の **カスタム CSS** で寄せられる。

```css
#alert-text {
  transform: translateY(-130px);
}
```

`margin` ではなく `transform` を使う。Streamlabs のアラートは画像とテキストが
単純な縦積みになっていないので、`margin` は効かないことがある。`transform` は
レイアウトの計算に関係なく描画位置だけをずらすので、構造に関わらず動く。

数値は表示している大きさに比例する。800×600 を 100% で使う場合、カード下の余白は
(600 − 320) ÷ 2 = 140px なので、-130px あたりから調整するとよい。

セレクタが合っているか確かめたいときは、いったんこれを入れて赤帯が出るかを見る。

```css
#alert-text {
  outline: 3px solid red;
  background: rgba(255, 0, 0, 0.4);
}
```

アラートはブラウザソース（Chromium）で再生されるため、VP9 のアルファがそのまま効いて背景が抜ける。

Streamlabs 側の表示時間は 2〜300 秒まで指定できるが、このアプリの尺は **2〜30 秒**にしてある。
それ以上は書き出し時間もファイルサイズも実用的でなくなるため（6 Mbps だと 300 秒で 200 MB を超える）。
尺スライダーの横に推定サイズを出しているので、アップロードできる大きさかは書き出す前に分かる。

## レアリティ

| 保留色 | バッジ | 登場       | 主な演出                           |
| ------ | ------ | ---------- | ---------------------------------- |
| 白     | N      | フェード   | 光沢 2 回、粒がわずかに舞う        |
| 青     | R      | せり上がり | 青グロー、粒が舞う                 |
| 緑     | SR     | せり上がり | 光沢 3 回、粒が増える、衝撃波 1 本 |
| 赤     | SSR    | ズーム     | 集中線、衝撃波 3 本、震え、火花    |
| 金     | UR     | 叩きつけ   | 集中線、金枠、金粉、強い閃光       |
| 虹     | LR     | 叩きつけ   | 虹枠、虹のグロー、オーロラ、周回光 |

着地の演出は、数値を少しずつ変えるのではなく**上位でしか出ない要素**で切り分けてある。
そのほうが「何が出たか」で段が分かる。

- **衝撃波が出たら緑（SR）以上**。緑は 1 本、赤より上は 3 本重なる
- **集中線が走ったら赤（SSR）以上**
- **叩きつけ（バウンドする登場）なら金（UR）以上**

バッジの文字は表の値が初期値になるだけで、UI の「ランク表記」から自由に書き換えられる
（「激アツ」「確定」など）。空にすればバッジ自体が出なくなり、↺ でレアリティごとの初期値に戻る。

### 虹（LR）だけの演出

最上位は、ほかの段の「量を増やしただけ」に見えないよう、**種類の違う演出**を足してある。
どれも `scene.rarity.rainbowFrame` で分岐している。

- **虹のグロー** — カードの裏の光を枠と同じコニックグラデーションで染める。
  `shadowColor` には単色しか渡せないので、いったん白で形だけ作り `source-atop` で色を重ねる。
  枠と同じ角度で回すため、それぞれの辺でハローと枠の色がそろう。
  白を 3 割残しているのは、純色は白より輝度がずっと低く、完全に置き換えると急に暗く見えるため
- **オーロラ** — カード面を斜めの虹色の帯が 3.2 秒周期で流れ続ける。
  光沢（`drawShine`）の白い帯は登場後に決まった回数だけ走って終わるが、こちらは尺のあいだずっと動く。
  合成は `screen`。加算だと白く飛んでアートが消える
- **周回光** — 枠に沿って光が 2.4 秒で 1 周する。線を破線にしてギャップを周長いっぱいに取り、
  1 本だけ残したうえで `lineDashOffset` を時間で動かしている。座標を自前で追わずに済むので、
  角丸のままきれいに回る。枠の虹も同じ周期で回るので、光の色は常にその場の枠色に近い
- **虹の集中線** — 着地の集中線を 1 本ごとに枠色で塗る。一周で虹が 1 回りするよう並べてあり、
  6 色を繰り返さないのは枠との対応を崩さないため

プリセットは `src/card/rarity.ts` にまとまっている。色や粒の量はここを触れば変わる。

## 入りの演出（昇格）

カードが出る前に、光が中心に集まって膨らみ、弾けた瞬間にカードが出る前振りを挟める
（UI の「入りの演出」チェックボックス）。動きはどのレアリティでも同じで、**変わるのは光の色だけ**。

光は**必ず白から始まり**、保留カラーを 1 段ずつ上がって本来の色に着地する。
保留変化と同じ「色が変わった瞬間にアツくなる」を、段数のぶんだけ繰り返すことになる。

| レアリティ | 色の道のり                  | 段数 |
| ---------- | --------------------------- | ---- |
| 白         | 白                          | 0    |
| 青         | 白 → 青                     | 1    |
| 緑         | 白 → 青 → 緑                | 2    |
| 赤         | 白 → 青 → 緑 → 赤           | 3    |
| 金         | 白 → 青 → 緑 → 赤 → 金      | 4    |
| 虹         | 白 → 青 → 緑 → 赤 → 金 → 虹 | 5    |

**前振りの長さはスライダーで決める（0.5〜8 秒、既定 2 秒）。レアリティでは変わらない。**
段数に比例させると下位レアリティの前振りが一瞬で終わってしまい、演出として物足りなくなるため。
同じ長さの中で上位ほど多くの段を通るので、上位は色が速く連続して上がっていく（連続昇格）。

尺の 60% が上限で、尺が短ければ自動で縮む（縮んだときは「4.0 秒（尺に収まらないので 3.0 秒に短縮）」
のように UI に出る）。前振りを長く楽しみたいときは、尺のほうも合わせて伸ばす。

**動きの速さもどのレアリティでも同じ。** リングが吸い込まれる周期、光条の回転、粒が中心へ届く
速さ、弾ける速さは、すべて秒で固定してある。上位らしさは「何段上がるか」と
「光の強さ（段が上がるごとに一段大きく光る）」で出している。

中心の白い十字は回さない。回すと十字の形が崩れるので、向きは固定したまま
大きさで動かしている。縦横で位相を反転させてあるので、横が伸びるときに縦が縮む。
基準の長さを上限より下に取っているのは、上限で頭打ちになると周期の半分が
伸びきったまま固定され、止まって見えるため。

### 通す色を選ぶ

白と目的の色は必ず通る。その間のどの色を通すかは、チェックボックスで 1 色ずつ選べる。

| チェック（虹の場合）     | 道のり                      |
| ------------------------ | --------------------------- |
| 青 ・緑 ・赤 ・金 すべて | 白 → 青 → 緑 → 赤 → 金 → 虹 |
| 青 と 赤 だけ            | 白 → 青 → 赤 → 虹           |
| すべて外す               | 白 → 虹（一撃）             |

「全部」「一気に」のボタンで一括切り替えもできる。選んだ結果の道のりはその場に出るので、
書き出す前に確認できる。

前振りの長さは通る色の数では変わらないので、色が減るほど 1 段あたりの間隔が広がる。
白でいちばん長く溜めてから変わるのが「一気に」で、変化の瞬間のインパクトは最大になる。
青のように白から 1 段しかないレアリティでは、間に挟める色がないので選択肢そのものが出ない。

- 段数はレアリティだけで決まる。seed では変わらないので、同じレアリティなら毎回同じ段取りになる
- 色が変わった瞬間はリングが走って、変化を見逃さないようになっている
- 虹の `glowColor` は白で、そのまま使うと始点の白と見分けがつかない。
  虹の段だけは枠色を素早く巡回させて虹らしく光らせている

演出は `src/card/intro.ts` にまとまっている。色の段取りは `buildIntroStages` が組み立てる。

## 設計メモ

### ファイルの分かれ方

`src/card/` は、依存の向きが一方通行になるように割ってある。

| ファイル         | 役割                                                   |
| ---------------- | ------------------------------------------------------ |
| `scene.ts`       | 寸法・タイムライン・姿勢。canvas に触れない            |
| `compositing.ts` | 中間レイヤー・ディザ・縁のマスク。何を描くかは知らない |
| `card-face.ts`   | カード本体。矩形に貼りつく絵                           |
| `effects.ts`     | フレーム全体に広がる演出（衝撃波・集中線・閃光・粒）   |
| `intro.ts`       | カードが出る前の共通演出                               |
| `render.ts`      | 上を組み立てて 1 フレームにする入口                    |

`scene.ts` と `compositing.ts` が互いを知らないのが要で、
「どこに何が出るか」と「どう重ねるか」を別々に読める。

### プレビューと書き出しが絶対にズレないようにしている

描画は `renderFrameBlurred(ctx, time, scene, blur)`（`src/card/render.ts`）に集約されていて、
画面のプレビューも WebM の書き出しも、この同じ関数だけを呼ぶ。
結果が時刻 `time` のみに依存する純関数なので、見えているものがそのまま出る。

同じ理由で、パーティクルは毎フレーム位置を積分せず、生成時に決めたパラメータと経過時間から
位置を直接計算している（`src/card/particles.ts`）。積分方式だとシークした時に絵が変わってしまう。
乱数も `Math.random` ではなくシード固定の mulberry32 に統一してある。

### フェードは 1 枚のレイヤーにまとめてから合成する

カードはグロー・アートワーク・ビネット・枠・ラベルと、半透明の層を重ねて描いている。
この状態で層ごとに `globalAlpha` を掛けると、合成のたびに `1-(1-a)^層数` で不透明側に寄り、
フェードがほとんど効かない（実測で、想定 115 のところが 248 になっていた）。

そのため半透明の間だけ、いったんオフスクリーンのレイヤーに不透明で描き、
それを 1 回だけ `globalAlpha` 付きで合成している。レイヤーは描画先のコンテキストごとに
`WeakMap` でキャッシュしているので、プレビューと書き出しが同時に走っても互いを壊さない。

同じ理由で、パーティクル・ホログラム・衝撃波・周回光は `globalAlpha` を代入せず乗算している。
代入すると、カードがまだ透明な登場の頭でそれらだけが濃く出てしまう。

粒はカードの上に乗ったぶんだけ 35% まで薄くする。加算合成なので、濃いまま重なると
バッジや名前が読めなくなる。カードの外周で切ると矩形の線が見えるので、
縁から内側へ短辺の 6% の幅を使って滑らかに落としている。

### モーションブラーはサンプルを加算で平均する

描画が時刻だけで決まる純関数なので、1 フレームの露光時間のあいだで時刻をずらして
何度か描き、平均すればそのままモーションブラーになる。速度ベクトルを持ち回らずに済む。

合成は加算（`lighter`）で、各サンプルを 1/N の濃さで足している。`source-over` で
重ねると色は平均されるがアルファが平均されず、一枚でも不透明なサンプルがあれば
その場所は不透明のまま残る。結果、光が通り過ぎた跡が「不透明な暗い色」で埋まって
黒ずむ（実測で、光条のアルファが 255 のまま色だけ 184→133 に落ちた）。
加算ならプリマルチプライドのまま色もアルファも正しく平均される。

### 8bit への量子化は最後の 1 回だけにする

1/N に落とす計算を 8bit の canvas でやると、丸め誤差が避けられない。色 32 は 1/8 で
ちょうど 4 になるが 33 は 4.125 が 4 に落ちるため、隣り合う階調が潰れて暗部に縞が出る。
グローの勾配も同じで、なだらかなところほど同じ値が長く続き、その境目が等高線として見える。
白いグローのように広い範囲を薄く覆う絵ほど目立つ。

そこで中間レイヤーを float16 で持ち（`getContext('2d', { colorType: 'float16' })`）、
ブラーの平均も縁のマスクもその精度のまま積んで、8bit に落とすのは最後の 1 回だけにしている。
float16 が使えない環境では 8bit のまま動き、ディザだけを諦める。

最後の 1 回はそれでも残るので、量子化の直前に 1 レベル未満のノイズを足して、
どちらに丸まるかを画素ごとに散らしている。等高線が粒に変わって縞が消える。

ノイズは**光が乗っているところにだけ**撒く。全面に足すと透明なはずの一面が 0 と 1 の
まだらになり、VP9 はアルファを別の動画として持つぶん、それがそのままビットレートに乗る
（実測で 4 秒の書き出しが 3.76MB → 4.75MB）。合成結果を 16 回重ねて飽和させたものを
マスクにすると 3.87MB（+2.8%）に収まる。

### なぜ透過 WebM で、なぜ mediabunny なのか

- MediaRecorder はアルファ付き動画を出力できない
- Chrome 151 時点で、WebCodecs の `VideoEncoder` は `alpha: "keep"` を**サポートしていない**
  （`isConfigSupported` が VP8 / VP9 / AV1 のいずれでも `supported: false` を返す）
- mediabunny は色とアルファを 2 本の VP9 ストリームに分けてエンコードし、
  WebM の alpha side data として多重化するため、この制約を回避できる

書き出した WebM を `<video>` で再生して `drawImage` した実測値:

| 位置         | RGBA                   |
| ------------ | ---------------------- |
| フレーム四隅 | `[0, 0, 0, 0]`         |
| カード中心   | `[238, 234, 242, 255]` |
| グロー部分   | `[253, 213, 83, 144]`  |

グロー部分に中間のアルファが残っているとおり、1bit 透過ではなくフルアルファが保持されている。

書き出しの忠実度を確かめるときは、**実物のブラウザで測ること。** Playwright の
ヘッドレス Chromium は canvas から `VideoFrame` を作る段で色をアルファで乗算する。
実物の Chrome では乗算されない。ヘッドレスで測ると「グローが暗く焼き付いている」
という存在しない不具合が見える。

|                     | canvas            | VideoFrame        |
| ------------------- | ----------------- | ----------------- |
| 実物の Chrome       | `[255,199,64,32]` | `[255,199,64,32]` |
| ヘッドレス Chromium | `[255,199,64,32]` | `[32,24,8,32]`    |

描画のほう（`fingerprint.test.ts` など）はヘッドレスでも問題ない。
食い違うのは canvas から動画へ渡す一段だけ。

### フレームの縦横比がカードと違う理由

カードは 2:3 だが、出力フレームはそれより長辺方向に広く、カードは長辺の 58% しか使わない
（例: 900×700 のフレームに対しカードは 522×348）。

金や虹のグローはカード短辺の 4 割ほど（900×700 なら中心から 410px、フレーム半幅 450px）外に滲む。これがフレーム端で切られると、
透明に落ちきる前に断ち切られて、配信画面に四角い光の板が乗ってしまう。
そのため外周に余白を取ったうえで、次の 3 つを常にフレームの内側に収めている。

- グローは端に届く前に自分で消える濃さと広さにしてある。外側の拡散層はぼかし半径の
  1.5 倍・濃さ 0.35 で一度だけ重ねる。これ以上広げると余白に収まらない
- 着地の閃光は短辺の内側に収まる半径にし、塗る矩形もその範囲だけにする
- 衝撃波のリングは短辺の半分より内側で消える

カードを長辺の 58% に抑えているのは、スラム（登場時の 1.6 倍）でもフレームからはみ出さない
ためでもある。64% だと 900px 幅のフレームに対しカードが 922px になり、
余白が負になって `computeGlowBlur` のガードでグローが丸ごと消えていた。

最後の一手として、`fadeFrameEdges` がフレームの縁に向けてアルファを落とす。
形は**超楕円**（指数 2.5）。角丸の矩形で切ると、直角の内側だけ縦横のフェードが掛け算になって
急に落ち、等高線がそこで折れるので、丸いグローの中に四角い縁が浮き出てしまう。

幅は短辺の 6%（900×700 なら 42px、落ち幅は約 63px）。広いほど緩やかに溶けるが、
広げすぎるとスラムで膨らんだカードの角に届いて本体が透ける。粒を外してカード本体だけを描き、
マスクの前後で不透明な画素がどれだけ削られるかを尺全体で測ると、7% から削られ始める
（7% で 2、9% で 21、11% で 61）。6% なら 1 に収まるので、そこを上限にしている。

全レアリティについて 8x ブラーで尺全体を 0.05 秒刻みに走査し、フレーム端の
最大アルファが全時刻 0 であることを確認している。

向きが変わると幅と高さの役割が入れ替わるため、枠の太さ・角丸・文字の大きさ・グローの
広がり・粒の大きさは、幅ではなくカードの**短辺**を基準にしている。幅を基準にすると、
横向きのときにこれらがまとめて引き伸ばされてしまう。粒の飛ぶ速さだけは短辺ではなく
カード全体の大きさ `(幅+高さ)/2` に合わせている（短辺基準だと横向きで急に鈍くなるため）。

## デプロイ

Cloudflare Workers の静的アセットとして出している。サーバ側でやることが
何も無いので `main` は持たず、`wrangler.jsonc` に `assets` だけを書いてある。

main に push すると GitHub Actions が回り、整形・lint・型チェック・knip・
テスト・ビルドが通ってからデプロイされる。プルリクではビルドまで。

動かすには、リポジトリの Secrets に 2 つ入れる必要がある。

| 名前                    | 取り方                                                                                                   |
| ----------------------- | -------------------------------------------------------------------------------------------------------- |
| `CLOUDFLARE_API_TOKEN`  | Cloudflare のダッシュボード → My Profile → API Tokens。テンプレートの **Edit Cloudflare Workers** で作る |
| `CLOUDFLARE_ACCOUNT_ID` | Workers & Pages の概要ページの右側に出ている                                                             |

手元から出したいときは `pnpm exec wrangler deploy`。
何が上がるかだけ見たいなら `--dry-run` を付ける。

### 独自ドメインは手で割り当てる

`gachacards.11gather11.com` は Cloudflare のダッシュボードで割り当てている
（Workers & Pages → 対象の Worker → Settings → Domains & Routes → Add → Custom domain）。

`wrangler.jsonc` に `routes` と `custom_domain: true` を書けば自動で作れるが、
そうすると CI のトークンに**ゾーン全体の DNS 書き込み権限**が要る。
`11gather11.com` には他のものも載っているのに、設定は一度きりなのに、
毎回の push で走るトークンの権限だけが広がるので割に合わない。

`routes` を書かない限り、wrangler はドメインの割り当てに触らない。

## 公開用の画像

OGP 画像は、このツール自身の描画コードで作っている。イラストを別に用意するより、
実際に出るものを見せたほうが伝わるし、演出を変えたときに作り直すだけで追随できる。

```bash
pnpm exec vp dev              # 別の端末で開発サーバを立てておく
pnpm exec vp run assets       # public/og.jpg と apple-touch-icon.png を作る
```

favicon は手書きの SVG（`public/favicon.svg`）。16x16 まで縮むので、要素は
カードの枠だけに絞ってある。中身を描くと潰れてただの四角になる。

`index.html` の `og:url` と `og:image` は絶対 URL でないと拾われないので、
公開先のドメインに合わせること。

## アクセス解析

Cloudflare Web Analytics を使う。Cookie を使わないので同意バナーが要らない。

ビーコンは JS スニペットで入れる。ドメインは Cloudflare 経由だが、それだけでは
挿入されない。ダッシュボードの「サイトを追加」でホスト名を入れると
「JS スニペットをインストールする必要があります」と出る。

トークンは `CF_ANALYTICS_TOKEN` で渡す。渡さなければ何も差し込まれないので、
手元とプルリクのビルドは集計に載らない。ページに載せて使う公開値なので、
GitHub 側は secrets ではなく変数（`vars`）に置いている。

Web Analytics → サイトを追加 → ホスト名 → 完了 → 出てきたトークンを、
リポジトリの Settings → Variables に `CF_ANALYTICS_TOKEN` として登録する。

## 開発

Vite+ を使っている。詳細は `CLAUDE.md` を参照。

```bash
pnpm exec vp check --fix   # format + lint + 型チェック
pnpm exec vp test run      # テスト（実物の Chromium を立ち上げる）
pnpm exec vp run knip      # どこからも使われていない export を探す
pnpm build                 # 本番ビルド
```

`vp check` は型が通るかしか見ないので、使われなくなった export はそのまま残る。
knip はそれを見つける。pre-push フックでは 4 つとも走らせている。

`knip.json` で `@astryxdesign/theme-neutral` を除外しているのは、これが
`global.css` の `@import` からしか参照されず、knip が CSS を追わないため。
消すと配色のトークンが失われる。

### Astryx の版は固定してある

UI は Meta の [Astryx](https://astryx.atmeta.com)（React 19 + StyleX）に載せている。
peer が `@stylexjs/stylex ^0.19.0` で、このプロジェクトと一致する。

`@astryxdesign/core` と `theme-neutral` は**キャレットを付けずに固定**している。
まだ Beta で、2 か月のあいだに版が 1176 個出ている。破壊的変更を
`pnpm update` で黙って拾わないようにしておく。

上げるときは版を明示して、UI を一通り触ってから入れること。

```bash
pnpm add @astryxdesign/core@x.y.z @astryxdesign/theme-neutral@x.y.z
```

CSS レイヤーの順は `index.html` の `<head>` で宣言している。順序は
「最初に現れた場所」で決まるので、`global.css` に書くと StyleX の
`priority*` が先に登録され、あとから来る Astryx の `reset` に負けて
こちらで指定した padding や背景が消える。

### テスト

カードの描画は OffscreenCanvas・float16 キャンバス・コニックグラデーション・
影のぼかしに依存していて、どれも Node には無い。そのため Vitest の
ブラウザモードで、実物のブラウザ（Playwright）の中で走らせている。
初回だけ `pnpm exec playwright install chromium webkit` が要る。

**Chromium と WebKit の両方で回している。** Safari と iOS で崩れていないかを
見るため。実際、`ctx.filter` のぼかしは WebKit では設定が通るのに黙って
無視される。縁のマスクがぼけないまま掛かり、光が角の立った板になって
出ていた。設定できたかどうかでは分からず、描いて測って初めて見つかる類なので、
エンジンを 2 つ回す価値がある。

そのため縁のぼかしには `ctx.filter` を使わず、形を画面の外に置いて影だけを
所定の位置に落としている（`fadeFrameEdges`）。影のぼかしはどちらのエンジンでも
効く。影は sigma がぼかし半径の半分なので、`filter` の 2 倍を指定すると
同じ広がりになる。

`src/card/render.test.ts` は、全レアリティ × 5 つの時刻で 1 フレーム描き、
その**指紋**を snapshot に残す。ピクセルをそのままハッシュにすると
ラスタライザの 1 段の違いで落ちてしまうので、画面を 12×9 の格子に割って
アルファと色の平均を 16 段階に丸めたものを並べている。

```
000000000000|002578875200
002455554200|06abbbbbba60
02aeffffea20|2a97676669a2
```

左がアルファ、右が色。目で見てカードの形が分かるので、落ちたときに
どこが変わったのかが読める。グローの色を 0.70 から 0.72 に変えるだけで
3 つの snapshot が落ちる程度には効いている。

**この指紋の比較は手元の Chromium でだけ走らせている。** 同じ Chromium でも macOS と
Linux ではぼかしの結果が 1 段ずれることがあり、実測で 30 件中 14 件が
食い違った。丸めを粗くしても境目は残るので閾値では消せない。
許容誤差でも駄目で、上の「本物の変更」を測ると動いたのは 13 セル、
ずれはどれも 1 段だった。プラットフォーム差と同じ幅なので、1 段を許すと
本物の変更まで見逃す。

リファクタは手元で起きるし、pre-push フックが push の前に全部走らせるので
守りとしては足りている。CI では環境に依らない性質（描き直しの一致・
縁が透明であること）だけを見る。

`src/card/scene.test.ts` のほうは絵を描かない部分（寸法・タイムライン・
色の段取り・粒の再現性）で、「どうあるべきか」を書いてある。

`vp check` は型が通るかしか見ないので、使われなくなった export はそのまま残る。
knip はそれを見つける。pre-push フックでも走らせている。
